# Inference runtimes are pluggable, selected per session

The deployment target is an Advantech UBX-330M (Intel Core Ultra 5 125H): 14 cores, AVX-VNNI, an Arc integrated GPU, and an NPU whose driver isn't loaded. Plain PyTorch on CPU in float32 — what the code did originally — uses none of that acceleration, and `pick_device()` only ever chose between Apple MPS and CPU.

Rather than pick one optimised stack, transcription goes through a `Runtime` interface (`runtimes.py`) with one method, `transcribe(audio, language) -> str`. Implementations: `pytorch` (MPS/CPU, works anywhere), `openvino-gpu` / `openvino-cpu` / `openvino-npu` (Intel GPU/CPU/NPU, one converted IR between them), `ctranslate2` (int8, which AVX-VNNI accelerates), and `whispercpp` (GGML). The runtime is chosen per session — CLI `--runtime`, or the panel's Runtime field — so the same machine can be measured several ways without code changes.

This is worth the indirection because the right choice genuinely isn't knowable in advance: it depends on the machine, and the only way to settle it is to measure each one on the same clip. `probe()` reports which runtimes are usable *and why the others aren't* (library missing, no Intel GPU present, weights not converted), because "unavailable" has several distinct causes with different fixes, and a bare greyed-out option would leave the operator guessing.

Everything except `pytorch` needs its own weight format, so the weights are converted once per machine by `convert_model.py` into `models/`. That's a real cost: several GB per runtime per model, and the conversion is a step that can fail on a fine-tuned model. Only the CTranslate2 conversion has been verified end-to-end (on macOS); the OpenVINO and whisper.cpp paths are written but unverified against real Intel hardware.

**Consequence worth knowing:** decoding parameters have to be matched across runtimes or the comparison is meaningless. faster-whisper defaults to `beam_size=5` with a temperature-fallback ladder, while the PyTorch path decodes greedily in a single pass. Left alone that made CTranslate2 look several times slower than it is. `CTranslate2Runtime` therefore pins `beam_size=1`, `temperature=0.0`, `condition_on_previous_text=False` to match. Any future runtime has to be checked the same way.

**Language is part of that parity, and originally wasn't.** `ctranslate2` and `whispercpp` hardcoded `language="th"`, while `pytorch` and both OpenVINO paths passed nothing and so let Whisper auto-detect per chunk. Two runtimes were therefore doing strictly less work than the other three, on top of producing different output for the same audio — the same class of invisible unfairness as the `beam_size` mismatch, but harder to spot because both behaviours look correct on Thai audio. `language` is now an argument to `transcribe()` that every runtime honours identically, and auto-detection is an explicit choice (`auto`) rather than a per-runtime accident. The set of offered languages lives in `transcribe.LANGUAGES` alone, served to the panel over `GET /languages`.

**The set of models is discovered, not declared.** It was originally two keys written out in four files, so adding a model meant editing all of them and forgetting one produced an unexplained 422. `model_catalog.py` instead assembles the list from what is installed — the two builtin Typhoon fine-tunes, `models.local.json`, Whisper models in the Hugging Face cache, and converted weights under `models/` — and `GET /models` rebuilds it per request so a model installed while the server runs is offered immediately. The cost is that "which models exist" is now a question about the machine rather than about the code: it can differ between two checkouts, callers must ask rather than assume, and model keys reaching the filesystem have to be validated as path-safe because they come from disk. Worth it, because the alternative made trying any model outside the original two a code change.
