# Dedupe keyword detections with a time-window debounce, not word-level timestamps

Keyword spotting needs to avoid double-alerting when a keyword falls in the 1-second overlap between two chunks (see ADR 0001). The natural fix — request word-level timestamps from the model and only search the "new" (non-overlap) portion of each chunk — doesn't work here: Thai script has no spaces, and the model's word-alignment heuristic groups on whitespace, so it returns the entire chunk's transcript as a single timestamp span rather than per-word boundaries.

Instead, keyword detection dedupes by remembering when each keyword/phrase text was last alerted, and suppressing a repeat alert of the same keyword within a debounce window. That window has to be sized to the chunk *step* interval (chunk length minus overlap) plus a small buffer — not the overlap duration itself — because an overlap-caused duplicate always lands exactly one chunk later (one step apart), not within the overlap window. With the current 5s chunk / 1s overlap settings, that's roughly 4.5s, not ~2s as initially assumed. This trades away detecting a genuine repeated utterance of the same keyword within that window — acceptable for spotting whether a keyword was said at all, not for precise occurrence-counting.
