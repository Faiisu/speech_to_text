# Speech-to-Text and Backend integrate via plain HTTP POST over an append-only event log

The Speech-to-Text service and the new Backend service are split so the Speech-to-Text service can keep running natively (it needs real microphone access, which is awkward from inside a container), while the Backend and its TimescaleDB run in docker-compose. They communicate over a plain synchronous HTTP POST from Speech-to-Text to a Backend ingest endpoint whenever a keyword is detected — no message queue, no retry logic beyond a short request timeout. This is a deliberate simplicity choice for a single-machine demo with low event frequency (only fires on keyword detections, not continuously); a queue would add operational complexity with no benefit at this scale.

The backend stores detections as an append-only event log (word, detected_at, model, session_id) rather than a mutable per-word counter, despite the original framing of the requirement as "+1 to the database." This matches TimescaleDB's time-series design, and a simple running total is just `COUNT(*)` over the event log — so nothing is lost by storing the finer-grained history, and it enables time-windowed queries (e.g. "how many times in the last hour") that a bare counter could never answer.
