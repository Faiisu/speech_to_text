# Skip transcription on silent chunks instead of trusting the model

Whisper-family models (including Typhoon Whisper) have no "say nothing" output: fed silence or quiet background noise, they still generate plausible-sounding text — a well-known hallucination failure mode. Since every chunk during a live session gets transcribed unconditionally, silent gaps between speech were producing hallucinated transcripts, including false keyword-spotting alerts and false detection events sent to the backend.

Each chunk (and the final full-clip reference pass) is now gated by a simple RMS energy check (`is_silent`, default threshold `0.02`) before it's sent to the model at all; chunks below the threshold are logged as skipped rather than transcribed. This is a blunt instrument compared to a real voice-activity-detection model, but it directly targets the failure mode this project actually hit, without adding a new dependency. The threshold is exposed via `--silence-threshold` since the right cutoff depends on microphone gain and background noise, which vary per machine/environment.

This gate is necessary but not sufficient: real-world testing showed ambient room noise can sit above the default threshold, still reaching the model and hallucinating — in one case as a repetition loop (the same phrase regenerated dozens of times), a distinct Whisper failure mode from ordinary silence hallucination. `transcribe()` now also passes `no_repeat_ngram_size` and `repetition_penalty` generation kwargs to stop the looping specifically; a single hallucinated word from noise that clears the RMS threshold can still occur; the fix for that is tuning `--silence-threshold` upward for the actual environment, not something this gate can solve for every microphone out of the box.

The generation settings that mitigation added — `no_repeat_ngram_size=3` and `repetition_penalty=1.3` — were subsequently made per-session settings and **defaulted off** (`0` and `1.0`). Two reasons. `whispercpp` cannot receive them at all (pywhispercpp exposes no generation knobs), so applying them everywhere else meant no two runtimes were ever decoding on the same terms, and every cross-runtime transcript comparison was measuring the settings as much as the runtime. And they are blunt in a way that matters for Thai specifically: a repetition penalty punishes every token already emitted and cannot distinguish a hallucinated loop from a speaker repeating themselves, which Thai does constantly (`ครับ`, `ค่ะ`, greetings). On the project's own clip, where the speaker says `สวัสดีครับ` three times, `repetition_penalty=1.3` replaced the genuine repeats with invented words (`สุขสวนต์ครัป การเซ็กซ์ สวยค่ะ ฤๅจิม`) while `1.0` transcribed them correctly — and this was initially misread in the other direction, the correct repeated transcript mistaken for the very looping failure the setting exists to prevent. A repeated transcript is evidence of nothing until it is checked against the audio. Plain greedy is now the neutral baseline; the guards remain one flag (or one field) away for audio that actually loops, and `benchmark.py --repetition-penalty 1.0,1.3,1.5` sweeps them with the transcripts printed side by side. The looping failure this ADR describes is real and unchanged — what changed is that the fix is now applied deliberately rather than assumed.

The silence threshold default was subsequently raised from `0.01` to `0.02` after `0.01` proved to sit below the noise floor of real microphones in use, letting room tone through to the model. `0.02` is still only a starting point, not a universally correct value — it depends on microphone gain and room noise, which is why it stays exposed as a setting.
