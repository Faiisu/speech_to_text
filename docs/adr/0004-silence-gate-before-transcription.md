# Skip transcription on silent chunks instead of trusting the model

Whisper-family models (including Typhoon Whisper) have no "say nothing" output: fed silence or quiet background noise, they still generate plausible-sounding text — a well-known hallucination failure mode. Since every chunk during a live session gets transcribed unconditionally, silent gaps between speech were producing hallucinated transcripts, including false keyword-spotting alerts and false detection events sent to the backend.

Each chunk (and the final full-clip reference pass) is now gated by a simple RMS energy check (`is_silent`, default threshold `0.01`) before it's sent to the model at all; chunks below the threshold are logged as skipped rather than transcribed. This is a blunt instrument compared to a real voice-activity-detection model, but it directly targets the failure mode this project actually hit, without adding a new dependency. The threshold is exposed via `--silence-threshold` since the right cutoff depends on microphone gain and background noise, which vary per machine/environment.

This gate is necessary but not sufficient: real-world testing showed ambient room noise can sit above the default threshold, still reaching the model and hallucinating — in one case as a repetition loop (the same phrase regenerated dozens of times), a distinct Whisper failure mode from ordinary silence hallucination. `transcribe()` now also passes `no_repeat_ngram_size` and `repetition_penalty` generation kwargs to stop the looping specifically; a single hallucinated word from noise that clears the RMS threshold can still occur; the fix for that is tuning `--silence-threshold` upward for the actual environment, not something this gate can solve for every microphone out of the box.
